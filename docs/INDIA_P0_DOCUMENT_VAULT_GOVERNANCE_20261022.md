# INDIA Secure Document Vault — governance extension (P0)
Date: 22 October 2026. Branch: `feat/india-p0-vault-uat-20261022`, PR #23.

## Existing release (migration 0015)
The original PR stores encrypted, authenticated evidence for Proposal, Submission, customer Negotiation, PO/SPK, Contract, and Award Letter on the active offer release. AES-256-GCM and SHA-256 are calculated on the server; Cloudflare Access authentication and Sales ownership are checked on upload, list and download. This existing, isolated UAT Worker remains on the previously deployed release until re-deployed and re-tested.

## New functionality (migration 0021; NOT yet deployed to UAT/production)
1. **Pre-release originals:** `/api/sales/document-vault` uploads NDA, RKS, KAK, Quotation, or supporting PDFs/DOCX/PNG/JPEG/EML to a real Opportunity even when no Presales release exists. Original bytes remain AES-GCM encrypted in D1 chunks. All document references use server-calculated SHA-256. No anonymous/public object URL is generated.
2. **Unified workspace:** `/sales/documents` lists both pre-release and release evidence with version, digest, author, retention and legal-hold status. Sidebar and mobile navigation link to it. Existing Sales/Presales file picker remains fully functional.
3. **Immutable version history:** Every new original gets a monotonically increasing version per Opportunity and document category, without overwriting previous bytes. Migration 0021 backfills version metadata for every original stored under 0015 and leaves those stored originals unchanged.
4. **Retention:** An independent Admin may set a future retention-until date, but not shorten an existing deadline; the value remains unset until the institution confirms its policy. When an archive is overdue and there is no legal hold, download access is limited to Admin/Legal. Both old and new download routes enforce this, preventing bypass through a historical link. There is no automatic physical purge, deletion or retroactive shortening.
5. **Legal hold:** Admin/Legal can set a hold, but only Legal can release it. A maker may not authorize governance changes to their own document. A reason of 15–500 characters is mandatory.
6. **Immutable audit:** Upload/download, retention and legal hold events record actor email/role, document ID, scope, action, and timestamp in `india_document_access_events`; updates and deletes are rejected by triggers. Auditing must succeed before the authenticated download returns plaintext. The existing India Sales audit also receives an event.
7. **Authorization:** All business roles require validated Cloudflare Access JWT and active D1 membership; Sales can access only their own Opportunity. Viewer is denied. Finance/Approver/Legal may view originals but never upload them as maker; Presales uploads only release Proposals or RKS/KAK/supporting files.

## Boundaries and release gates
- The original PR #23 UAT deployment contains **migration 0015 only**. Source changes and the new migration 0021 are in GitHub and CI; do not equate CI fixture identities with human Cloudflare Access UAT.
- PR #24 owns migrations 0016–0020. The numbering in 0021 is deliberately reserved to avoid collisions. 0021 depends on 0015, but not on migrations 0016–0020. Its `india_schema_migrations` row must be verified by exact version number, not just `MAX(version)`.
- Before touching the existing isolated D1 UAT: export SQL backup, validate a restore, record and preserve the D1 time-travel bookmark, check schema 0015, verify 0021 migration rollback on a clone, and only then apply 0021 transactionally. Never auto-apply migration from CI. Check `PRAGMA foreign_key_check` and `PRAGMA quick_check` and confirm historic checksums/chunk counts are unchanged.
- Deploy **exactly the reviewed and CI-green source SHA** to the isolated `uat-india-vault` Worker with existing private encryption-key secret, D1 binding and Access audience. Do not rotate the encryption key while documents are stored. Confirm `/sales/documents` and negative-download status codes by real HTTP requests.
- Run genuine signed Cloudflare Access sessions as Sales A, Sales B, Admin, Presales, Finance, Legal, Approver, Viewer. Verify owner isolation, self-approval denial, invalid file signatures, size bounds, version concurrent uploads, governance policy, overdue download denial and independent Legal hold release.
- Production deployment, retention deletion jobs and regulatory retention durations require separate release approval. D1 original storage has a practical capacity ceiling; plan encrypted R2 offload and malware-scanning infrastructure before large-scale deployment. No malware scanning is claimed.

## Tests
The source now includes `tests/document-vault-governance.test.cjs`, connected to `npm run test:document-vault`, which runs in both GitHub CI workflows. It covers pre-release NDA/RKS/KAK/Quotation, full-byte download, versioning and immutability, role ownership, expiry, legal hold, missing encryption key, upload signatures, audit fail-closed and migration rollback. The original 0015 test suite is retained. A green CI result verifies source behaviour with isolated fixture identities, not completed cloud-role UAT.
